# Defender and Monitoring Notes

## Purpose and boundaries

This project is intended only for approved awareness exercises with advance notice. It is not designed to evade browser controls, SIEM detection, endpoint monitoring, or network security tools. Do not use it for covert tracking or to test defenses outside a written scope.

## Expected observable activity

Depending on platform configuration and telemetry, defenders may observe:

- access to the static hosting origin;
- a browser geolocation permission prompt and a browser location API call after the user clicks the start button;
- an outbound HTTPS request from the browser to the configured `script.google.com` web-app endpoint;
- Apps Script executions and changes to the designated Google Sheet;
- browser console messages generated by the page.

Network and endpoint visibility varies by browser, managed-device policy, DNS/proxy logging, Google Workspace audit coverage, and SIEM/EDR integrations. This list is not exhaustive and is not a promise that every event will be recorded.

## Safe validation

For a sanctioned exercise, coordinate with the SOC and endpoint administrators in advance. Agree on scope, test accounts, timestamps, allowed domains, expected event types, escalation contacts, and stop conditions. Use synthetic coordinates or a controlled test device. Verify detections from approved telemetry; do not disable controls, hide indicators, rotate infrastructure to avoid blocks, or tune the page to bypass monitoring.

The current implementation's endpoint is called with `no-cors`, so client-side behavior cannot confirm that Google stored a record. Use Apps Script execution history and the test Sheet to validate the collector.
